# 캐릭터 구조 검수 — 3.0.0-audit.1

공식 캐릭터 58명을 실제 CharacterDataService로 컴파일하고 함수 없는 동결 데이터·Trigger·공격 참조·반격 계약·AttackSpec 태그를 검사했다. 이전 작업에서 전체 소스의 구문·결합 스코프·캐릭터 ID 분기·게임플레이 타이머·자원 변경 후보를 검색하고 확인한 오류를 수정했다. 이 기록은 모든 가능한 실행 상황에 오류가 없다는 보장이 아니다. 캐릭터별로 공통 모듈 설정이 다른 정상적인 고유 기술은 유지한다. 유저 캐릭터 제작 기능은 추가하지 않는다.

## 발견과 교정

| 대상 | 수정 |
|---|---|
| 충전 반격 | 획득량 +1·새 획득 시 활성 시간 초기화로 설명 변경. 기존 counter.stock에 modifier.constant(stat:maxStamina, value:-0.20) 조합. 기존 최대 보유량 +1 효과 유지. |
| 체리티 | allowNoCc 우회 제거. ccRefAttackId로 기존 반격 공격의 movement.neutralize-knockback을 참조. 선딜 300ms와 연막/은신/속도 효과 유지. |
| 반 | Training의 수리 계산을 기존 ProgressStateService.updateIdleRepair로 이동. 스패너 전용 설정 참조를 공통 수리 설정 값으로 교체. 완료 시 미정의 repair 참조 수정. |
| 이동 공통·타우·시아넬리 | 기존 TagService에서 이동기 태그 파생. 적중·벽 적중·온라인 확정의 별도 흔적 생성 제거. 시아넬리 교환 이동의 중복 흔적 제거. MovementAbilityService가 표현 설정과 권위를 사용해 단일 생성. |
| 시아넬리·디라 | 기본 LMB 홀드와 중복된 repeatWhileHeld:true 설정 제거. |
| 디라 | 5개 공격의 수동 파생 태그 제거. 실제 모듈로부터 TagService가 계산. 의미 태그는 유지. |
| 키·뉴 | 지연 회복과 반격 후속 공격을 SimulationScheduleService로 통합. source 생존·예약 정리에 따라 취소. |
| 키 | 회피 종료 보상 타이머 fallback 제거. 기존 dodge-ended 이벤트로 단일 확정하며 취소·세션 초기화 시 대기 보상 정리. |
| 공통 Trigger·장판 | 회복의 미정의 now를 이벤트 시각으로 수정. 전역 주기의 미정의 frameScale 인자 제거. 현재 공식 캐릭터가 쓰지 않는 경로도 회귀 검사. |
| 버프 공통 | regenPercent 감소 방향에 -100% 하한 정의. |

새 게임플레이 모듈을 추가하지 않았다. 기존 CharacterDataService, TagService, BuffService, ProgressStateService, CounterModuleService, MovementAbilityService, EffectSpawnService, SimulationScheduleService와 이벤트 경로를 재사용했다. 목표 지점/투사체 이동은 런타임 목표 거리가 distance 입력이므로 정적 수치가 하나만 있는 정상 구성을 오류로 처리하지 않았다. 피해 반영과 원격 스냅샷·부활·소환수 자원 변환은 구분하여 검토했다.

## 우선 플레이 테스트

훈련장 후 2인 온라인에서 양쪽 화면을 확인한다.

| 캐릭터 / 증강 | 확인할 항목 |
|---|---|
| 아무 캐릭터 + 충전 반격 | 1중첩 최대 스테미나 80%, 2중첩 60%, 제거 후 복구. 반격 획득량 +1과 새 획득 시 보유 반격 시간 초기화. |
| 체리티 | 반격 300ms 뒤 적중·무력화 넉백·연막·은신 유지, CC 중복 없음. |
| 반 | 스패너 0 후 현재 데이터의 대기 500ms·누적 수리 4500ms로 완전 수리. 이펙트 1회, 미고갈 내구도 초당 25 회복. 수리 중 행동 중단·누적 진행 유지. |
| 키 | 장판 회피 종료 보상, 저스트 회피 제외, 회피 취소 보상 없음, 333ms 지연 회복, 대기 중 사망 시 회복 취소. |
| 뉴 | 반격 후속 공격의 순서·간격·피해, 대기 중 사망/라운드 초기화 시 취소. |
| 타우 | 평타 적중·벽 적중 이동과 흔적 1회, 양쪽 화면 일치. |
| 시아넬리 | LMB 홀드, RMB 정지 투사체 교환 위치·도착 공격·흔적 1회와 상대 화면. |
| 디라 | LMB 홀드, 재료·식사·스토브·반격 태그와 판정, 스토브 체력 1000 유지. |
| 유이·리안·루뷰 | 공통 이동 흔적 회귀: 적중 이동/방패 대시/망치 접근. 루뷰 자가 넉백에는 이동 흔적 없음. |
| 셰리나 비아 | 이전 수정 회귀: 방패 차단 잔향 범위와 상대 화면의 연속 표시. |
| 나머지 캐릭터 | 공통 서비스 영향 확인을 위해 LMB·RMB·반격 각 1회와 일반 이동기의 기본 점검. |

## 검사 명령 및 한계

- `node tools/test-structure.cjs`: 58명 전체 구조 + 실제 서비스의 11개 검사 묶음. 외부 서비스 경계 일부는 테스트 대역을 사용한다.
- `node tools/test-gameplay-fixes.cjs`: 기존 게임 회귀 15개.
- `node tools/test-room-connection.cjs`: 모의 연결 회귀 17개.
- `python tools/project.py check`, `python tools/verify.py`: 역할·문서 최신화와 배포/원본 UI·미변경 리소스·등록·규칙 보존 검사.

실제 브라우저 렌더링·WebRTC 실전·Firebase 로그인은 미검증이다. 특정 ID로 분기하는 캐릭터 실행 예외는 이전 검색·검토에서 발견되지 않았으나, 이름 분기가 없다는 사실만으로 모든 구조 규칙이 충족되는 것은 아니다. 대형 객체 내부 책임 분리·네트워크와 시뮬레이션의 기존 결합은 README에 남은 구조 과제로 계속 기록한다.

## 58명 데이터 구조 결과

전원 컴파일·동결·함수 없음·능력 Trigger·반격 계약/CC 참조·공격 참조·AttackSpec 의미 태그 검사를 통과했다. 직접 플레이 완료를 뜻하지 않는다.
