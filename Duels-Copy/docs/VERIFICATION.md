## 발견 및 수정
첫 분할의 정규식이 규칙 주석 내부의 `<style>` 문구를 실제 태그로 오인했다. 이 때문에 메인 CSS에 규칙 문장이 혼입되고, 규칙 문서 후반이 누락되었다. 실제 HTML 파서로 태그/주석 경계를 구분해 원본에서 다시 추출했다. 원본의 모든 규칙·주석을 복원했다. Windows 로캘에 의존하던 Python 텍스트 입출력도 UTF-8로 고정했다.

## 검증 한계와 남은 구조 작업
실행 가능한 브라우저가 없어 실제 화면, 훈련장 조작, Firebase 로그인 및 온라인 대전은 검증하지 못했다. 이번 검수는 분할 시 발생한 변경·누락 여부를 확인하며, 원본 게임에 이미 있던 전투 버그의 부재를 보장하지 않는다.
ESM 전환, 대형 서비스 객체 내부 책임 분리, 전투/네트워크 결합 정리는 이번에 구현하지 않았다. 유저 캐릭터 제작 기능도 추가하지 않았으며 공식 캐릭터의 데이터 계약만 문서화했다.

재현: `python tools/verify.py`, `python tools/project.py check`. 전자는 초기 분할 기준 원본 동일성 검사이므로 이후 의도적인 기능 수정에서는 별도 회귀 검사가 필요하다.

## split.3 시작 오류 회귀 검사
Windows의 LF→CRLF 저장 차이를 모든 프로젝트 텍스트에 적용한 임시 복사본에서 문서 검사와 전체 원본 대조를 통과했다. 실제 내용 변경은 엄격 검사에서 실패를 탐지했다. 문서가 오래된 상태에서도 서버 HTML/runtime 응답이 정상이며 시작 단계 CalledProcessError가 발생하지 않는 것을 확인했다. 서버는 문서를 자동으로 수정하지 않았다. docs 실행 후 엄격 검사는 다시 통과했다. 필수 캐릭터 파일이 실제로 누락된 경우에는 시작을 중단하고 파일 누락 안내를 출력했다.
실제 Windows Python 3.13에서 직접 실행한 검사는 아니다. 사용자 PC에서 달라진 구체적인 파일은 로그만으로 확인할 수 없다.
