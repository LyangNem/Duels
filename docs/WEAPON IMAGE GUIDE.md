# 공용 무기 이미지 제작 규칙

버전: 3.0.0-character.135

월드 장착 무기는 모든 캐릭터가 같은 `ModeGearPresentationService`를 사용한다. 캐릭터 전용 draw 함수와 캐릭터 ID 분기를 추가하지 않는다. 공격 판정·무기 투사체는 기존 공격 모듈의 책임이다.

## 화살비 장판 중심 넉백 — 3.0.0-character.175

실제 장판 state.execution=null인 경우 중심좌표가 전달되지 않아 기본0rad 오른쪽넉백이 되던 원인 수정. 실행정보가 없으면 공용 AttackExecutionService.create로 생성 후 실제장판 중심 전달.

InstalledAreaFieldService.fieldTrigger에서 실제 area.center를 point impactOrigin으로 전달. away-from-impact 공용효과가 장판중심을 읽음. 생성타격의 기존 착탄중심 유지.

실제와 동일한 execution=null·시로이동후 상하좌우4방향 넉백 회귀 및 시로·무기 회귀 및 build/docs/check/verify/runtime구문/ZIP무결성 통과. 실제온라인 플레이 미검증.

## 디자인

기존 무기의 고유 형상을 유지한다. 단색 한 가지로 강제하지 않으며 해당 계열의 면/선/장식 색과 명암을 허용한다. .117에서 변경했던 총·검·작살·스패너·기어는 .116 형상/팔레트로 복원했다. 뉴/레이카 검은 칼날과 가드를 유지하고 면 그립·감김선·끝마개로 손잡이를 표현한다. 헤브 작살은117 형태에서 축/날/그립을 다듬었다. 시로 활은 가는 곡선 팔다리와 뾰족한 끝으로 표현하며 차징 화살을 그리지 않는다.

형상은 공용 목록에 데이터로 보관한다. paths의 fillColor는 같은 계열의 면/장식 색을 지정한다. 미지정 시 캐릭터색 기반 어두운 면을 사용한다. 모든 윤곽/내부선은 캐릭터/무기색을65% 밝힌 공용 색을 사용한다. lineWidth는 반경 비례 수치지만 면 외곽1.8px/내부선1.35px에서 제한한다. 큰 검을 확대해도 선이 과하게 두꺼워지지 않는다. stroke:false는 면만 그린다. 여러 캐릭터에 새 스타일을 추가할 때 캐릭터 전용 그리기 함수를 만들지 않는다.

1. `src/data/WEAPON_IMAGE_DEFS.js`에 style 이름과 정규화 좌표를 추가한다. `paths`는 points 또는 M/L/C/A/Z commands, fill/closed를 사용한다. `rings`는 반경 또는 x/y/radius, `string`은 start/end/restX/pullX로 시위 변형을 정의한다. 데이터만 작성한다.
2. 캐릭터의 `worldEffectModules`에 아래 모듈을 추가한다. 이미 있는 형상이면 해당 style만 선택한다.
3. 공격의 기존 `mode.toggle` when:on-delivery로 회전/사용 상태를 변경한다. 실제 ProjectileService.spawn 또는 AreaAttackService.execute가 AttackModuleService.onDelivery를 호출하고 Trigger event attack.delivery 조건을 검사한다. canonical execution effectKey로 산탄/반복은1회만 적용한다. 선딜 예약/취소/사망에는 모션을 생성하지 않는다. 직접 전달이 없는 이동 자체의 연출은 after-attack을 유지한다. 기존 ModeState/ChargedAttack/TimedAction/Progress snapshot이 상대 화면에도 같은 타임라인을 전달한다.
4. 역할 등록, PATCH LOG, docs/check/build 및 실제 표시 검수를 수행한다.

```json
{
  "type": "effect.spawn",
  "renderType": "weaponImage",
  "style": "harpoon",
  "color": "#9a6848",
  "scale": 1.5,
  "angle": -0.6,
```

`scale`은 캐릭터 반경 배율, motion 이동도 반경×scale에 비례한다. 짧게 예비 동작→빠른 발사→긴 복원으로 작동한다. `rotationStateKey/rotationMs/rotationRadians`는 전체 회전이며 기본2π, 인투는 -2π로 반시계방향. `chargeStateKey`는 기존 차징 상태의 진행도를 시위와 `motion.chargeRotation`에 반영한다.

`conditions`는 기존 Trigger 조건을 사용해 장착/파괴/투척 상태를 판별한다. `alpha` 기본 .85, `alphaVariants`는 첫 일치 조건의 배율을 곱하며 상대 화면도 동일하다. 재장전은 activeOnly:true여서 완료 유지 구간에는 이미 밝아진다. `idleAlpha/useHoldMs/useFadeMs`는 사용 시 밝아졌다가 평소 투명도로 복원하는 공용 옵션이다. 기존 본체 은신/숨김 알파를 곱하므로 무기도 같은 은신 처리를 따른다. 무기 출현/제거/종류/색 변화는 기존 공통 전환 링을 사용한다.

## 인투와 레이카 실행 계약

인투 `intu-ammo`는 기존12발 탄창, `intu-sniper`는 남은 변환 횟수다. 반격 때 state.progress add4/growMax:true 뒤 최초 발사분 subtract1. growMax는 명시한 add에만 유한 max를 확장하고 다른 자원의 고정 상한은 유지한다. 저격탄도 일반 탄창을 소비한다.12발 고갈 시 기존1500ms 재장전으로 탄창만 복원하며 변환 잔량은 유지한다. 여러 반격으로12발 넘게 누적 가능하다. 잔량0 자동 일반 총 복귀, RMB 성공 시 잔량0 강제 복귀. 기존12칸 탄창 중 남은 변환 횟수만큼 활성 칸을 앞에서부터 하늘색으로 바꾸며 별도 탄창은 없다. gauge.segmented의 highlightCountRef가 intu-sniper 실제 progress를 읽고 highlightColor가 #9bdcff를 지정한다. 탄창을 초과해 누적되면 현재 활성 탄창 전체가 강조되고 남은 변환 횟수는 재장전 뒤에도 보존된다. 인투는 highlightFrom:right로 남은 활성 탄창 오른쪽부터 하늘색을 채운다. 색 변형 colorOverride와 강조 개수는 공용 렌더 인자로 전달해 원본 segment 배열을 변경/복제하지 않는다.

레이카 일반 RMB의 공격 전 preview.create는 requireResource:true를 사용한다. 공통 AttackService.previewReady에서 준비된 실제 공격 비용으로 StaminaService.canSpend를 확인한다. 부족하면 preview 체인을 진행하지 않아 선딜 잠금도 생성되지 않는다. 이미 비용을 낸 공격 뒤 미리보기(requireExecuted:true)에는 재검사를 하지 않는다. 선행 차징 등 다른 캐릭터의 기존 preview는 기본 동작을 유지한다.
